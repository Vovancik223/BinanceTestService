# Binance Price Service

REST-сервис для получения, хранения и анализа средней цены торговых пар Binance.

Приложение периодически запрашивает среднюю цену выбранной торговой пары через Binance API, сохраняет полученные значения в PostgreSQL и предоставляет REST API для получения последней цены, расчёта средней цены, просмотра истории и определения тренда.

По умолчанию используется торговая пара `BNBUSDT`.

## Технологии

- Java 21
- Spring Boot 3.5.7
- PostgreSQL
- Liquibase
- Maven
- JUnit 5
- Mockito
- WireMock

## Требования

Для запуска приложения необходимы:

- Java 21 или выше.
- Maven.
- PostgreSQL.

## Настройка базы данных

Создайте базу данных PostgreSQL:

```sql
CREATE DATABASE binance_prices;
```

Параметры подключения настраиваются через переменные окружения.

| Переменная | Значение по умолчанию | Описание |
|---|-|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/binance_prices` | URL подключения к PostgreSQL |
| `DB_USERNAME` | `postgres` | Имя пользователя PostgreSQL |
| `DB_PASSWORD` | | Пароль пользователя PostgreSQL |
| `SERVER_PORT` | `8080` | Порт REST API |
| `BINANCE_BASE_URL` | `https://api.binance.com` | Базовый URL Binance API |
| `BINANCE_SYMBOL` | `BNBUSDT` | Торговая пара |
| `BINANCE_POLL_INTERVAL` | `PT30S` | Интервал получения цены в формате ISO-8601 |


## Запуск приложения

Клонируйте репозиторий и перейдите в его корневую директорию.

Соберите проект:

```bash
mvn clean package
```

Запустите приложение:

```bash
mvn spring-boot:run
```

После запуска Liquibase автоматически применит миграции базы данных.

По умолчанию REST API будет доступен по адресу:

```text
http://localhost:8080
```

## REST API

Все endpoints имеют общий префикс:

```text
/api/v1/prices
```

### 1. Получение последней сохранённой цены

**GET** `/api/v1/prices/latest`

Возвращает последнюю сохранённую запись для настроенной торговой пары.

Пример запроса:

```http
GET http://localhost:8080/api/v1/prices/latest
```

Пример ответа:

```json
{
  "symbol": "BNBUSDT",
  "price": 850.12345678,
  "fetchedAt": "2026-10-20T10:00:00Z"
}
```

Если в базе данных отсутствуют записи, возвращается HTTP `404 Not Found`.

### 2. Получение средней цены за период

**GET** `/api/v1/prices/average`

Параметры запроса:

| Параметр | Тип | Описание |
|---|---|---|
| `from` | Instant | Начало периода |
| `to` | Instant | Конец периода |

Пример запроса:

```http
GET http://localhost:8080/api/v1/prices/average?from=2026-10-20T00:00:00Z&to=2026-10-21T00:00:00Z
```

Пример ответа:

```json
{
  "averagePrice": 850.12345678
}
```

Для расчёта используется интервал `[from, to)`: начальная граница включается, конечная — нет.

Если за указанный период нет записей, возвращается HTTP `404 Not Found`.

### 3. Получение истории цен

**GET** `/api/v1/prices`

Возвращает историю сохранённых цен за указанный период с поддержкой пагинации.

Параметры запроса:

| Параметр | Тип | Значение по умолчанию | Ограничения |
|---|---|---|---|
| `from` | Instant | — | Обязательный |
| `to` | Instant | — | Обязательный |
| `page` | Integer | `0` | Не меньше 0 |
| `size` | Integer | `20` | От 1 до 100 |

Пример запроса:

```http
GET http://localhost:8080/api/v1/prices?from=2026-10-20T00:00:00Z&to=2026-10-21T00:00:00Z&page=0&size=20
```

Пример ответа:

```json
{
  "items": [
    {
      "symbol": "BNBUSDT",
      "price": 850.12345678,
      "fetchedAt": "2026-10-20T10:00:00Z"
    },
    {
      "symbol": "BNBUSDT",
      "price": 849.98765432,
      "fetchedAt": "2026-10-20T09:59:30Z"
    }
  ],
  "page": 0,
  "size": 20,
  "totalElements": 2,
  "hasNext": false
}
```

Записи сортируются по времени получения в порядке убывания.

Для выборки используется тот же полуоткрытый интервал `[from, to)`.

### 4. Определение тренда цены

**GET** `/api/v1/prices/trend`

Параметры запроса:

| Параметр | Тип | Описание |
|---|---|---|
| `from` | Instant | Начало периода |
| `to` | Instant | Конец периода |

Пример запроса:

```http
GET http://localhost:8080/api/v1/prices/trend?from=2026-10-20T00:00:00Z&to=2026-10-21T00:00:00Z
```

Пример ответа:

```json
{
  "symbol": "BNBUSDT",
  "start_date": "2026-10-20",
  "end_date": "2026-10-21",
  "trend": "UPWARD"
}
```

Возможные значения `trend`:

- `UPWARD` — последняя цена выше первой.
- `DOWNWARD` — последняя цена ниже первой.
- `FLAT` — первая и последняя цены равны.

Тренд определяется сравнением первой и последней сохранённых цен за указанный период. Он не характеризует каждое промежуточное изменение цены.

Если за указанный период нет записей, возвращается HTTP `404 Not Found`.

## Обработка ошибок

Приложение обрабатывает ошибки REST API и возвращает соответствующие HTTP-статусы.

| HTTP-статус | Описание |
|---|---|
| `400 Bad Request` | Некорректные параметры запроса или ошибка валидации |
| `404 Not Found` | Запрошенные данные отсутствуют |
| `500 Internal Server Error` | Внутренняя ошибка приложения |

Ошибки Binance API также обрабатываются отдельно. В частности, учитываются ограничения частоты запросов и ответы с HTTP `429` и `418`.

Пример структуры ответа с ошибкой:

```json
{
  "timestamp": "2026-10-20T10:00:00Z",
  "status": 404,
  "message": "Price not found"
}
```

## Тестирование

Для тестирования используются:

- **JUnit 5** — написание тестов.
- **Mockito** — изоляция тестируемых компонентов и имитация зависимостей.
- **WireMock** — имитация ответов Binance API в интеграционных тестах.
- **PostgreSQL** — отдельная тестовая база данных.

Для интеграционных тестов используется база `binance_prices_test`. Её необходимо предварительно создать:

```sql
CREATE DATABASE binance_prices_test;
```

Тестовый профиль `application-test.yml` использует отдельную базу данных и WireMock вместо настоящего Binance API.

Для запуска тестов:

```bash
mvn test
```

Для полной проверки и сборки проекта:

```bash
mvn clean verify
```
